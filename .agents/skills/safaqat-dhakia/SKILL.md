# منصة صفقات ذكية

## الهوية والمشروع

- الاسم: منصة صفقات ذكية / Algerian Smart Public Procurement Platform.
- الهدف: منصة SaaS جزائرية لإدارة دورة حياة الصفقة العمومية من التخطيط إلى الإعلان، استلام العروض، التقييم، الإسناد، التعاقد، التنفيذ، الاستلام، والدفع.
- المستودع المرجعي: https://github.com/rabahkarrouche6-dev/smart-public-procurement-dz.git
- التقنيات الأساسية: Django REST Framework، PostgreSQL، React، Docker، REST APIs، وطبقة ذكاء اصطناعي مساعدة.
- اللغة الافتراضية للواجهات والوثائق: العربية بتنسيق RTL.

## الإطار القانوني

- المرجع الأساسي: القانون رقم 23-12 المؤرخ في 5 أوت 2023 المتعلق بالمشتريات العمومية.
- مرجع تنظيمي مكمّل: المرسوم الرئاسي رقم 15-247.
- المبادئ الواجب مراعاتها في كل شاشة ووظيفة:
  - حرية الوصول إلى الصفقات العمومية.
  - المساواة في معالجة المتعاملين الاقتصاديين.
  - الشفافية في الإجراءات والقرارات.
  - تتبع قابل للتدقيق لكل عملية وقرار.
  - عدم منح الذكاء الاصطناعي صلاحية قرار نهائي أو تنفيذي.

## بنية المنتج

تتكون المنصة من صفحة هبوط عامة وثلاث بوابات مترابطة:

| المكوّن | المستخدم | الوظائف الأساسية |
|---|---|---|
| صفحة الهبوط | الزائر | تقديم المنصة، تحويل الزائر إلى أحد المسارات الثلاثة، شرح القيمة والامتثال والأمان |
| بوابة المصلحة المتعاقدة | الجهة العمومية | إنشاء الصفقات، دفاتر الشروط، إدارة الآجال، استلام وتقييم العروض، الإسناد، متابعة العقود |
| بوابة المتعامل الاقتصادي | المورّد | اكتشاف الفرص، متابعة الآجال، إعداد العروض، رفع الوثائق، متابعة حالة المشاركة |
| بوابة الرقابة والتحليل | الجهات الرقابية والإدارية | مؤشرات الأداء، قيمة الصفقات، مراحل التنفيذ، التنبيهات، تقارير الشفافية والامتثال |

## دورة حياة الصفقة

اتبع هذه المراحل في النماذج وواجهات API ولوحات التحكم:

1. التخطيط والاحتياج.
2. إعداد دفتر الشروط والوثائق.
3. نشر الإعلان.
4. استفسارات المتعاملين وتوضيحات دفتر الشروط.
5. استلام العروض والوثائق.
6. الفحص الإداري والفني والمالي.
7. التقييم والمقارنة.
8. الإسناد والطعون عند الاقتضاء.
9. إبرام العقد.
10. التنفيذ والتعديلات.
11. الاستلام المؤقت والنهائي.
12. الأداء والدفع والإغلاق.

## قواعد التصميم

- استخدم واجهة مؤسسية حديثة، موثوقة، عربية RTL، مناسبة لـ GovTech وEnterprise SaaS.
- استخدم خط Cairo في الواجهات.
- اعتمد لوحات تحكم بالبطاقات، المؤشرات، الخطوط الزمنية، والتنبيهات.
- وحّد تجربة المستخدم عبر `WorkspaceShell` أو مكوّن هيكلي مشابه.
- حافظ على تمييز واضح بين الأدوار والصلاحيات.
- لا تعرض بيانات حساسة أو قرارات حساسة دون صلاحية مناسبة.

## قواعد هندسة النظام

- ابنِ الـ Backend على Django REST Framework مع تطبيقات واضحة للمستخدمين، الصفقات، العطاءات، العقود، التنفيذ، والتقارير.
- استخدم PostgreSQL كمصدر بيانات أساسي.
- طبّق صلاحيات مبنية على الأدوار: مصلحة متعاقدة، متعامل اقتصادي، رقابة/تحليل، إدارة النظام.
- افصل منطق الذكاء الاصطناعي في `AI Gateway` أو خدمة مساعدة.
- الذكاء الاصطناعي مخصص للدعم فقط: تلخيص، استخراج، تنبيه، اقتراح، فحص اكتمال؛ ولا يقرر الإسناد أو التقييم النهائي.
- كل عملية حساسة يجب أن تكون مسجلة في سجل تدقيق.

## سير العمل عند أي مهمة

1. حدّد الجزء المتأثر: واجهة، Backend، نموذج بيانات، API، عقد، امتثال، أو توثيق.
2. راجع التوافق مع القانون 23-12 ومبادئ الشفافية والمساواة.
3. لا تعدّل ملفات قائمة أو فرع `main` دون فحص.
4. اعمل على فرع مستقل عند تنفيذ تغييرات جوهرية، مثل `backend-foundation` أو `ui-polish`.
5. أنشئ أو حدّث النماذج، الـ serializers، الصلاحيات، واجهات API، والاختبارات.
6. وثّق الملفات المنشأة أو المعدّلة، نقاط API، الضوابط الأمنية، والاختبارات.
7. اذكر العوائق المتبقية وأمر التشغيل الدقيق.

## معايير القبول

- لا توجد تعارض صريح مع القانون 23-12.
- كل دور يستطيع الوصول فقط إلى وظائفه المسموح بها.
- كل مرحلة من دورة حياة الصفقة قابلة للتتبع.
- كل قرار حساس يبقى بشريًا وقابلًا للتدقيق.
- الواجهات عربية RTL ومتوافقة مع الهوية المؤسسية.
- لا يُدّعى اكتمال Django أو PostgreSQL أو Docker أو الاختبارات دون مخرجات فعلية تثبت ذلك.

## مخرجات مطلوبة عند إنجاز مهمة

عند نهاية أي تنفيذ، قدّم:

1. الملفات المنشأة أو المعدّلة.
2. نماذج قاعدة البيانات.
3. نقاط API.
4. ضوابط الأمان والصلاحيات.
5. الاختبارات المنفذة ونتائجها.
6. العوائق المتبقية.
7. الأمر الدقيق لتشغيل المشروع أو الجزء الجديد.
