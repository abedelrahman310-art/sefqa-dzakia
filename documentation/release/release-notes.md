# ملاحظات الإصدار الرسمي (Release Notes) — v1.0.0-rc1
**المنصة:** صفقات ذكية (Safaqat Dhakia) — المنظومة الرقمية الوطنية لإدارة وتدقيق الصفقات العمومية  
**تاريخ الإصدار:** 2026-11-05  
**فرع الإطلاق:** `release-closeout`  
**المرجعية التشريعية:** القانون رقم 23-12 والمرسوم الرئاسي رقم 15-247  

---

## 1. نظرة عامة على الإصدار

يمثل هذا الإصدار (`v1.0.0-rc1`) الإغلاق الإنتاجي الرسمي لمنصة «صفقات ذكية»، حيث تم إخضاع البنية التحتية والبرمجية بالكامل لتدقيق أمني وهندسي شامل، تصفير أي بيانات وهمية أو اختبارية، وتأمين تدفقات الصفقات العمومية وفق دورة حياة كاملة تبدأ من إعداد دفاتر الشروط وتنتهي بالإشراف الرقابي المركزي والتحكيم في الطعون.

---

## 2. الميزات الرئيسية والمحاور الوظيفية

### أ. بوابة المتعامل الاقتصادي (Economic Operator Portal)
- **الملف الإداري الرقمي الموحد (DZ-Passport):** تمكين المؤسسات والمتعاملين من حفظ واعتماد وثائق التأهيل والتصنيف والسجل التجاري والقدرات المالية للترشح بنقرة واحدة.
- **الدرع الامتثالي ومطابقة الفرص:** فحص آلي يمنع الإقصاء الشكلي عبر التحقق من استيفاء الوثائق القانونية المطلوبة قبل إيداع العروض.
- **الإيداع المشفر للعروض (Sealed Digital Bids):** تشفير كامل للأظرفة التقنية والمالية مع ختم زمني مشفر يمنع فتح أو كشف الأسعار قبل انعقاد الجلسة الرسمية.
- **حاسبة مراجعة وتحيين الأسعار:** احتساب تقلبات تكلفة المواد وفق الصيغة التعديلية للمرسوم 15-247.

### ب. بوابة المصلحة المتعاقدة (Contracting Authority Portal)
- **مُنشئ دفاتر الشروط التفاعلي (Smart Specs Wizard):** توليد دفاتر شروط متوافقة بنودها مع القانون رقم 23-12.
- **تجميد دفاتر الشروط ببصمة رقمية SHA-256:** تجميد إجرائي غير قابل للتلاعب قبل النشر لمنع التعديل اللاحق.
- **إدارة جلسات فتح الأظرفة الرقمية المباشرة:** بث حي ومحضر رقمي فوري يوثق العروض المقبولة والمبالغ المعلنة، مع تصدير محضر الجلسة المعتمد بصيغة PDF.
- **المنح المؤقت وتتبع مهلة الـ 10 أيام للطعون:** عدّاد زمني قانوني دقيق يوثق تواريخ النشر وآجال الطعن.

### ج. بوابة الرقابة المركزية (Hawk Eye — عين الصقر)
- **رصد شبهات التواطؤ وتجزئة الصفقات:** خوارزميات للكشف عن تدوير العطاءات وتجزئة النفقات لتفادي رقابة اللجان.
- **سجل التدقيق الجنائي المتسلسل (AuditLog Append-Only):** سجل رقابي يوثق كل توقيع وإجراء وتنزيل مع بصمة تجزئة SHA-256.
- **المعالجة والتحكيم في الطعون الإلكترونية:** استقبال الطعون وفحص أسبابها وإصدار قرارات البت الرقابي الملزمة.

## 3. التحسينات الأمنية والهندسية المنفذة في هذا الإغلاق

1. **تصفير البيانات وحظر البذر التلقائي:**
   - ضبط المتغير `ENABLE_DEMO_DATA=false` كقيمة افتراضية صارمة في كافة الإعدادات وبيئات التشغيل.
   - استحداث أمر الإدارة الآمن `python manage.py purge_demo_data` لتنظيف البيانات التجريبية دون المساس بالحسابات الإدارية والمشرفين.
2. **تصحيح الادعاءات التسويقية واللغوية:**
   - تصحيح كافة العبارات غير الدقيقة (مثل ادعاءات اللابل أو الأرقام والنسب المئوية غير المدعومة) لتكون صياغات تقنية وقانونية محايدة.
   - استبدال وصف "غير قابل للتعديل" بالوصف الهندسي الدقيق: "سجل تدقيق تراكمي مشفر برمجياً (Append-Only) ببصمة SHA-256".
3. **التسجيل المهيكل وعزل البيانات الحساسة (Structured Logging):**
   - تفعيل إطار التسجيل المهيكل في Django مع مرشح `SensitiveDataFilter` لحجب كلمات المرور، ورموز التوثيق JWT، وأسرار الدفع، والأسعار المالية السرية من السجلات.
4. **تأمين بيئة الحاويات (Docker Orchestration):**
   - إضافة فحوصات السلامة (Health Checks) لجميع الحاويات الأربع (`safaqat_postgres_prod`، `safaqat_redis_prod`، `safaqat_django_prod`، `safaqat_nginx_prod`).
   - تفعيل نقطة التحقق من الصحة المركزية `/api/health/`.

## 4. المخاطر المعروفة وخطط التخفيف التشغيلي (Known Risks & Mitigations)

| المخاطر المحتملة | مستوى الأثر | إجراءات التخفيف المعتمدة |
| :--- | :---: | :--- |
| **انقطاع اتصال قاعدة البيانات أثناء الذروة** | متوسط | وجود آلية إعادة الاتصال التلقائي عبر `docker-compose` وسجل healthcheck يكتشف الانقطاع خلال 15 ثانية ويعيد تشغيل الخدمة. |
| **محاولات الهجوم على واجهات برمجة التطبيقات (API Abuse)** | منخفض | تطبيق الـ Throttling بمعدل 60 طلب/دقيقة للمجهولين و 120 طلب/دقيقة للمسجلين، و 15 محاولة/دقيقة لنقاط الدخول. |
| **تضارب توقيتات الأجهزة مع التوقيت الرسمي** | منخفض | توحيد المنطقة الزمنية على الخادم والحاويات على `Africa/Algiers` ومزامنة أختام الجلسات مع التوقيت الوطني. |

## 5. تعليمات الترقية والنشر

1. سحب فرع `release-closeout` بعد الموافقة الرسمية.
2. التأكد من وجود ملف `.env` الإنتاجي المكتمل وفق `.env.example`.
3. بناء الواجهة الأمامية وتشغيل الحاويات:
   ```bash
   cd client && npm run build && cd ..
   docker compose -f docker-compose.prod.yml up -d --build
   ```
4. التحقق من سلامة الخدمات عبر:
   ```bash
   curl -f http://localhost/api/health/
   ```
