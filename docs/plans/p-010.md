# خطة تنفيذ المهمة P-010 — إعادة تصميم صفحات التسجيل (Register Redesign)

## الهدف
إعادة تصميم صفحات التسجيل الثلاث (Operator / Authority / Central) بمظهر عصري احترافي متناسق 100% مع الهوية البصرية، مع المحافظة التامة على:
1. جميع الحقول الحالية (بدون حذف، وبدون إضافة إلزامية تؤثر على الـ API).
2. منطق التسجيل والمصادقة (API contracts، الحفظ، التوجيه).
3. دعم كامل لـ RTL واللغتين العربية والفرنسية (i18n).

## نطاق التحسينات التفصيلي

### 1. المكونات المشتركة
- `RegisterHero.tsx`:
  - شاشة سطح المكتب: معالم الجزائر (مقام الشهيد)، علم الجزائر، الزخرفة الهندسية، الشعار، العنوان الرئيسي، 3 ميزات ملونة (تركواز، أزرق، بنفسجي)، والشعار السفلي.
  - شاشات الجوال (<768px): هيدر مضغوط وأنيق (الشعار والعنوان فقط).
- `RegisterRoleTabs.tsx`:
  - 3 تبويبات (المتعامل الإقتصادي، المصلحة المتعاقدة، الإدارة المركزية) مع أيقونة أعلى النص.
  - التبويب النشط بلون كحلي داكن `#0A2540`.
  - التنقل السلس بين `/register/operator` و `/register/authority` والتعامل مع الإدارة المركزية.

### 2. تقسيم النموذج إلى 3 بطاقات بصرية
- **بطاقة 1: بيانات الهوية** (الاسم الكامل، البريد الإلكتروني، رقم الهاتف).
- **بطاقة 2: معلومات الدور** (الولاية مع خيارات البحث، ورقم السجل التجاري / رمز المصلحة المتعاقدة حسب الدور).
- **بطاقة 3: الأمان وبيانات الدخول** (كلمة المرور مع مؤشر القوة 4 مستويات وزر الإظهار/الإخفاء، تأكيد كلمة المرور مع فحص التطابق الفوري، ومربع الشروط مع اهتزاز عند عدم الموافقة).

### 3. التحقق الفوري (Inline Validation)
- البريد الإلكتروني: regex رسمي مع رسالة خطأ فورية.
- الهاتف الجزائري: regex `^0[567]\d{8}$` مع رسالة توضيحية.
- مقياس قوة كلمة المرور: 4 درجات مرئية (ضعيف، مقبول، قوي، قوي جداً).
- مطابقة كلمة المرور الفورية أثناء الكتابة.

### 4. زر الإنشاء وحالاته الثلاث
- Idle: كحلي داكن `#0A2540` مع أيقونة `UserPlus`.
- Loading: Spinner مع "جارٍ الإنشاء...".
- Success: علامة صح خضراء مع "تم بنجاح" قبل التوجيه التلقائي.

### 5. التحقق والاختبار
- `pnpm --filter client typecheck`
- `pnpm --filter client build`
- فحص الاستجابة للشاشات (375px, 768px, 1440px)
- التحقق من عدم وجود أخطاء في الـ Console
- توثيق Handoff في `docs/TASKS.md`
